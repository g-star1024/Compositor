# Compositor 开发铁律（本项目强制规范）

> 适用范围：g-star1024/Compositor（robbietilton/Compositor 的 fork）。所有改动提交前必须逐条自查。
> 目标形态：macOS 14+ 通用架构（arm64 + x86_64）+ 简体中文（zh-Hans）。

---

## 铁律 1 — 部署目标与 API 可用性

- 最低部署目标锁定 **macOS 14.0**。禁止未经评估把 `MACOSX_DEPLOYMENT_TARGET` 改回 26.0 或只支持更高版本。
- 任何调用 **macOS 15 / 26 独占 API** 的代码，必须用 `@available(macOS 15, *)`（或实际所需最低版本）显式守卫，并提供 14.0 可用的回退路径。
- 修改部署目标后，**必须本地 `xcodebuild build` 跑通一遍**，按编译器报出的 availability 错误逐一修复，禁止靠"应该没问题"放行。

## 铁律 2 — 架构必须通用

- `ARCHS` 固定为 **`"arm64 x86_64"`**（通用二进制）。禁止改回仅 `arm64`（除非产品决策明确放弃 Intel Mac）。
- 交付前用 `file Compositor.app/Contents/MacOS/Compositor` 核验产物同时包含 `x86_64` 与 `arm64`。

## 铁律 3 — 本地化（i18n）强制

- 用户可见文案**一律走 String Catalog**（`Compositor/Localizable.xcstrings`），development language = English（Base），目标语言 `zh-Hans`。
- SwiftUI 中 `Text("字面量")` / `Button("字面量")` / `.navigationTitle("字面量")` 等用**字符串字面量**即可自动查表；动态拼接串用 `String(localized:)` 并补 key。
- **禁止在源码里写死面向用户的英文/中文混排文案。**
- 新增任何 UI 文案，必须同步在 catalog 中加入 key 与 zh-Hans 译文；缺译文的视为改动未完成。
- 改完本地化后，切换系统语言到中文实测；无实测条件时至少保证 catalog 编译通过且 key 完整。

## 铁律 4 — 版本号与发布同步

- 版本号来源：Xcode 工程 `Compositor.xcodeproj/project.pbxproj` 的 build settings `MARKETING_VERSION` 与 `CURRENT_PROJECT_VERSION`。`Config/Info.plist` **不含**显式版本键，由 Xcode 从 build settings 注入。
- 改版本时**必须同步**两处工程配置：`project.pbxproj` 的 `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION`，以及根目录 `appcast.xml`、`README.md` 的 Requirements 段落。
- 语义化版本：新增系统/架构支持、新增语言属兼容增强 → minor 位（如 1.4.6 → 1.5.0）；破坏性变更才动 major。

## 铁律 5 — Sparkle 自动更新

- 保留 Sparkle 依赖（自动更新是产品能力），禁止为本地构建方便而长期改掉远程引用。
- 若启用自动更新，必须把 `Info.plist` 的 `SUFeedURL` 指向**本 fork** 的 appcast 原始地址，并**重新生成 `SUPublicEDKey`**（上游的 key 不属于本 fork）。不改则自动更新不可用，但不影响手动安装。

## 铁律 6 — 构建与签名

- 本地未签名构建用于验证；正式分发**必须** `scripts/release.sh`：Developer ID Application 证书 + `xcrun notarytool` 公证凭据 + `create-dmg`，否则 Gatekeeper 会拦截。
- 本机（WorkBuddy 沙箱）跑构建需关闭外层沙箱（xcodebuild 内部的 sandbox-exec 在受限 shell 下会被拒），属本地可逆操作。
- Sparkle 经 SPM 远程拉取会被本机代理拦截。本地验证可临时 vendoring（见工程 skill），**提交/发版前必须还原为远程引用且不得提交 `Vendor/`**。

## 铁律 7 — 源码推送与打 tag（本环境特殊流程）

- 本机代理禁止直连 `github.com` 的 git 协议，`git clone` / `git push` 不可用。获取源码用 GitHub API tarball；推送与打 tag 走已连接的 **GitHub MCP / Git Data API**（见工程 skill）。
- tag 命名严格 `vX.Y.Z`，annotated tag 指向发版 commit。
- 推送前确认：已还原 Sparkle 远程引用、未含 `Vendor/`、版本号三处一致、构建通过。

## 铁律 8 — 代码风格（对齐上游）

- 美式拼写（`color` 而非 `colour`），SwiftUI + AppKit，像素操作用 C。
- 改动匹配周边命名、注释密度与风格。
- 项目文件格式见 `docs/project-format.md`；保存结构变化时同步 `ProjectManifest.current` 与文档中的格式版本。
