## 亮点

- **支持 macOS 14 及以上**：最低部署目标由 macOS 26 下调至 14.0，覆盖更多在役设备。
- **通用二进制（Universal）**：同时支持 Apple Silicon 与 Intel Mac（`ARCHS = "arm64 x86_64"`）。
- **新增简体中文（zh-Hans）界面**：`Localizable.xcstrings` 覆盖 418 条用户可见文案，全量翻译。

## 技术修复与验证

### 1. 本地化符号冲突导致 CI 构建失败（已修复）

- **问题**：String Catalog `Localizable.xcstrings` 中，仅大小写 / 省略号差异的 key（如 `Canvas Size` 与 `Canvas Size…`、`Zoom In` 与 `Zoom in (⌘+)`）以及形似 Swift 关键字的 key（`Type`），在 `SWIFT_EMIT_LOC_STRINGS = YES` 开启时会被 Xcode 自动生成重名 Swift 符号（`GenerateStringSymbols`），导致 `xcodebuild build-for-testing` 直接失败（exit 65）。
- **根因**：本项目用 `Text("字面量")` 运行时查表做本地化，从不引用 Xcode 生成的 `Localizable.*` 符号，该开关纯属负担。
- **修复**：根因是 Xcode 26 的 "Generate String Catalog Symbols" 设置（`STRING_CATALOG_GENERATE_SYMBOLS`，app target 默认 `YES`）会对 catalog 中仅大小写/省略号差异或形似关键字的 key 生成重名 Swift 符号，导致 `GenerateStringSymbols` 步骤失败。将 `project.pbxproj` 全部配置的 `STRING_CATALOG_GENERATE_SYMBOLS` 置为 `NO`（本项目用 `Text("字面量")` 运行时查表，不依赖生成符号）。同时保留 `SWIFT_EMIT_LOC_STRINGS = NO` 以防止 Xcode 在构建时改动手工维护的 catalog。已写入 `docs/开发铁律.md` 铁律 3。

### 2. CI 对齐通用架构（arm64 + x86_64）

- **问题**：`verify.yml` 此前 `build-for-testing` 与测试均固定 `arch=arm64`，Intel（x86_64）兼容性在 CI 中完全未被覆盖。
- **改动**：
  - `build-for-testing` 改用通用 destination + `ARCHS="arm64 x86_64"` + `ONLY_ACTIVE_ARCH=NO`，在 arm64 runner 上强制产出双切片；
  - 新增 `lipo -info` 步骤断言产物同时含 `x86_64` 与 `arm64` 切片，缺失即失败；
  - 测试仍在原生 arm64 runner 执行（窗口测试在 Rosetta 下不稳定），x86_64 由链接阶段验证。
  - 与 `build-release.yml` 的通用打包口径一致；`timeout-minutes` 60 → 90。

### 3. macOS 14 高版本 API 兼容（已修复）

- **问题**：部署目标下调至 14.0 后，编译器分批暴露了 3 批 macOS 15+/26+ 独占 API，导致 CI 构建失败。
- **修复清单**：

| 批次 | 文件 | API | 最低系统 | 修复方式 |
|---|---|---|---|---|
| 1 | `UI/JPEGExportSheet.swift` | `ScrollPosition` / `.scrollPosition` / `.onScrollGeometryChange` | 15.0 | 改用 `ScrollViewReader` + `scrollTo`（13+ 可用） |
| 2 | `Rendering/EditorCanvas.swift`（裁剪）、`Rendering/InlineTextEditor.swift`（文本框）、`Rendering/TransformOverlay.swift`（变换） | `NSCursor.FrameResizePosition` / `.frameResize(position:directions:)` | 15.0 | `#available(macOS 15, *)` 包裹，14 降级 `.crosshair` |
| 2 | `UI/BlendModePicker.swift` | `NSPopUpButton.borderShape = .capsule` | 26.0 | `#available(macOS 26, *)` 包裹，14 不设（默认矩形） |

- **验证**：全库静态扫描确认无其他 15+/26+ API 残留；`#available` 包裹后 macOS 15+/26+ 仍用新 API，14 编译通过。
- **教训**：降低部署目标后，编译器逐文件分批暴露 availability 错误，正确做法是全库静态扫描所有 15+/26+ API 特征一次性修完，而非修一个推一个。已写入 `docs/开发铁律.md` 铁律 1。
